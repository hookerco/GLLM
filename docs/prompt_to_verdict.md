# Prompt-To-Verdict Proof Runs

The proof-run layer turns a CNC prompt and a machine setup ID into a local evidence packet. It does not treat model output as trusted. The model drafts G-code, local checks evaluate it against the selected setup, Vericut can optionally simulate it, and the packet records the proof trail.

## Run From An Existing Candidate

Use this path when G-code has already been generated by Streamlit, the legacy CLI, or a saved fixture:

```powershell
poetry run python -m gllm.proof.cli --registry config/vericut_setups.example.json --setup-id vericut96_haas_minimill_sample --prompt "Run the shipped Haas MiniMill sample control program." --candidate-gcode-file tests\fixtures\haas_minimill_sample_control.nc --output-root .proof-runs --scenario-id sample-haas-minimill-control-static
```

This writes `.proof-runs\<scenario-id>\evidence_packet.json` and `.proof-runs\<scenario-id>\evidence_packet.md`, plus per-attempt prompt, raw G-code, cleaned G-code, path plot when parseable, staged Vericut job files, and a top-level `operator_action`.

The checked-in control fixture mirrors the shipped Haas MiniMill sample program, adds explicit inch units for the static gate, and converts the sample's below-surface rapid Z plunges into feed moves. It exercises the complete local path: prompt, setup registry load, static machine-policy checks, candidate artifacts, Vericut project staging, and evidence packet writing. The sample registry requires explicit inch units, allowed tools, bounded feed/spindle values, safe rapid Z, and an axis envelope before a candidate can reach staging.

## Generate And Prove

To let the proof CLI call the configured model, omit `--candidate-gcode-file`:

```powershell
poetry run python -m gllm.proof.cli --registry config/vericut_setups.example.json --setup-id vericut96_haas_minimill_sample --prompt "Mill a simple square pocket." --output-root .proof-runs
```

Model generation needs the same credentials as the app, such as `OPENROUTER_API_KEY` for the default OpenRouter path. Use `--max-repair-attempts 1` to let rejected static or Vericut findings become one repair prompt.

Repair prompts are evidence-first. They include the original task, scenario ID, setup ID, previous status, previous candidate file path, setup constraints, exact findings, and the previous candidate G-code. The model is asked to repair only from those concrete findings.

## Run A Prompt Corpus

Use the corpus CLI to prove several saved candidate scenarios against one or more setups:

```powershell
poetry run python -m gllm.proof.corpus_cli --corpus config/proof_prompt_corpus.example.json --registry config/vericut_setups.example.json --output-root .proof-runs\corpus-smoke
```

`config/proof_prompt_corpus.example.json` includes nine scenarios:

- Haas MiniMill safe no-op live control
- Haas MiniMill live-control sample program
- passing Haas MiniMill square pocket
- missing units mode
- unsupported tool
- unsafe rapid Z
- motion outside the declared envelope
- passing multi-pocket program
- passing Haas VF3 second-setup drill pattern

Each scenario names an expected packet status. The corpus runner writes per-scenario evidence packets plus `corpus_summary.json` and `corpus_summary.md`.

## Vericut Execution

By default, proof runs stop after static checks and Vericut staging. Add `--run-vericut` only when the local Vericut install and license should be used:

```powershell
poetry run python -m gllm.proof.cli --registry config/vericut_setups.example.json --setup-id vericut96_haas_minimill_sample --prompt "Run a safe no-op Haas MiniMill program." --candidate-gcode-file tests\fixtures\haas_minimill_safe_noop.nc --output-root .proof-runs --run-vericut --timeout-seconds 900
```

The packet distinguishes `accepted_static_only` from `accepted_vericut`. A Vericut process exit code of `0` is still rejected when the parsed log reports blocking errors.

## Packet Statuses

- `accepted_static_only`: static checks passed and the Vericut job was staged, but Vericut execution was not requested.
- `accepted_vericut`: static checks passed and parsed Vericut output reported no blocking errors.
- `rejected_static`: local setup checks found concrete machine-policy issues.
- `rejected_vericut`: Vericut ran or produced a verdict packet with blocking log findings.
- `blocked_setup_registry`: the registry could not be loaded or the setup ID was unknown.
- `blocked_setup_paths`: the setup registry points at missing local Vericut paths.
- `blocked_generation_failed`: the model or candidate generator failed before a candidate could be checked.
- `blocked_staging_failed`: a candidate passed static checks but could not be staged into a Vericut job.
- `blocked_missing_dependencies`: the project template referenced local dependencies that could not be copied.
- `blocked_vericut_timeout`: Vericut execution exceeded the requested timeout.

## Operator Actions

Every packet and attempt includes an `operator_action` field:

- `ready_to_review`: Vericut accepted the candidate.
- `rerun_vericut`: static checks passed but Vericut was skipped or timed out.
- `fix_prompt`: generation, static checks, or Vericut findings point back to the candidate.
- `fix_setup`: registry paths, setup files, staging, or copied dependencies need attention.
- `manual_review_required`: the status does not fit a more specific action.
- `reject`: reserved for hard reject policies.

## Streamlit Surface

After G-code is generated in the app, the Proof Run panel can build the same packet from the current `st.session_state["gcode"]`. The panel defaults to `config/vericut_setups.example.json` and `.proof-runs`, keeps Vericut execution opt-in, and shows a compact status/action/attempts card before the expandable evidence JSON.

## Local Data Boundary

Registry entries, copied templates, fixtures, tool libraries, Vericut logs, plots, and `.proof-runs` folders stay local. Repair prompts should receive setup IDs and concrete finding summaries such as `unexpected_units`, `feed_rate_out_of_range`, or `axis_out_of_envelope`, not proprietary project files, unless an operator explicitly approves richer context.
